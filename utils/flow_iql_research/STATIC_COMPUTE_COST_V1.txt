현재 rank-mean 후보의 계산 비용 점검

근거: logs/diagnosis/flow_iql_research_20261026/analysis/static_compute_profile_v3/
summary.json, strict_audit_v1.json, comparison_v1.csv 및 54개 optimized HLO.
모든 소스와 HLO 내용의 SHA256을 확인했다. 이전 V1/V2 점검 프로그램의 실패
기록은 static_compute_profile_attempts_v1.json에 보존했다. 학습이나 평가에는
영향이 없었으며, 완료된 9개 환경의 결과는 V3만 사용한다.

이는 설치된 JAX 0.4.1 CPU 컴파일러의 정적 연산량 추정이다. GPU 시간,
실측 latency, throughput, 전력, 실제 메모리 대역폭을 측정한 수치가 아니다.
입력 값은 컴파일 시 동적 인자로 취급했다. 학습 batch는 256이다.
데이터 로딩·전송, 환경 실행, 체크포인트, 주기적 진단, Python 통계 처리는
제외한다. 행동 추론은 단일 관측에서 행동만 반환하는 계산 그래프다.

학습 비교는 실제 등록된 IFQL V2 및 완료된 FQL reference 설정을 사용한다.
IFQL 후보는 이동 환경의 폭512, 조작 환경의 폭256을 쓰고 FQL은 모두512다.
세 IFQL 학습자의 Q/BC 업데이트 각 1M, V 업데이트 각 2M을 모두 포함한다.
배포에서 쓰지 않는 나머지 두 BC의 학습 비용도 포함한다.

이동 네 환경에서 세 IFQL V2 학습자의 업데이트 FLOPs는 FQL의 약2.08~2.10배,
조작 다섯 환경에서는 약0.54~0.55배다. 동일한 1M 업데이트를 9개 환경에
실행하는 경우의 합계 비율은 1.23636이다. 세 base learner를 쓴다는 사실과
FQL 대비 세 배의 실제 학습 시간이 든다는 주장은 구별해야 한다.
이 수치 역시 equal-compute 실험을 대신하지 않는다.

추론은 후보가 BC flow10회 x 행동9개 및 twin-Q 세 묶음을 계산한다.
FQL은 한 번의 one-step actor를 사용한다. 후보의 행동당 추정 FLOPs는
FQL 대비 이동 환경 약143.75~144.24배, 조작 환경 약37.46~38.61배다.
따라서 FQL과 비슷한 배포 비용 또는 낮은 latency라는 주장을 해서는 안 된다.
같은 구조의 IFQL best32 추론과 비교하면 약0.375배다. 이는 행동 수와
critic 수의 계산 비교이며 새로운 성능 결과가 아니다.

배포에 의미상 필요한 파라미터는 첫 BC와 세 online twin-critic이다.
첫 학습자의 V/target-Q를 보관하는 재현 bundle의 파일 크기, optimizer를
포함한 학습 checkpoint 크기, 실제 배포 계산에 참여하는 파라미터 수는
서로 다른 비용 지표다. 확인된 수치는 comparison_v1.csv에 따로 기록했다.
