현재 우선 검증 후보는 IQLV2 + BC flow + 독립 critic 3개의 순위 평균이다.
9개 환경 모두 tau=.9, gamma=.999, learner 3개, action 후보 9개를 쓴다.
학습은 기존 official-style IFQLV2 그대로이고, 배포 시 첫 learner의 BC만
사용한다. 각 critic의 twin head는 min으로 합친다. 새로운 환경별 파라미터나
환경별 우승 기법을 섞는 과정은 없다.

value 쪽에서는 같은 target-Q를 고정한 V fitting 2회, fresh V bootstrap,
알려진 반환값 구간으로의 target projection을 사용한다. fitting을 더 하는
것이 실제 조건부 residual을 반드시 줄인다고 가정하지 않는다. projection은
참 target이 그 구간 안에 있으면 그 target에 대한 거리 증가를 막는다.
이것이 신경망 Q 출력 전체의 정확도나 정책 성공률 안정성을 보장하지는 않는다.
실제로 value 수정의 효과는 환경별로 달랐고, Gaussian9-task 개선은 Ant의
기여가 컸다. 모든 환경에 보편적으로 효과가 있다는 주장으로 확대하면 안 된다.

정책 쪽은 공개 IFQL 방식의 BC flow로 행동의 여러 모드를 표현하고, 그 후보를
critic으로 비교한다. critic마다 값의 스케일이 달라지면 단순 Q 평균은 큰
스케일의 critic에 더 큰 영향력을 준다. 각 상태에서 critic별 순위로 바꾸면
각 critic의 strictly increasing calibration 변화에 선택이 바뀌지 않는다.
단순 Q 평균도 독립적인 state offset에는 이미 불변이다. offset만을 순위
변환의 이유로 제시하는 것은 정확하지 않다.

구체적으로 후보 a_i의 critic j 점수는 다음이다.
  rank_j(i) = sum_l 1[Q_j(a_l) < Q_j(a_i)]
              + 0.5 * sum_l 1[Q_j(a_l) = Q_j(a_i)]
  score(i) = (rank_1(i) + rank_2(i) + rank_3(i)) / 3
  action = argmax_i score(i)
(rank-0.5)/(N-1)은 나머지 후보 중 균등하게 뽑은 비교 행동보다 critic이
더 높게 평가할 확률에 해당하며, 동률은 반 점을 준다. 이 정규화는 모든
critic에 같으므로 argmax를 바꾸지 않는다. 따라서 평균 순위는 critic을
동일 가중으로 뽑았을 때의 평균적인 상대 선호를 최대로 하는 규칙이다.
세 critic이 같은 순서를 주면 원래 IFQL best9와 같은 행동을 선택한다.
이는 표준적인 순위 집계 성질이며, 순위 계산 자체에 대한 신규성 주장은 아니다.
값의 거리 정보는 버리므로 항상 더 좋은 규칙이라는 성능 보장은 없다.

왜 중앙값 대신 평균인가도 동일 모델로 분리해서 확인했다.
                         평균         중앙값
  Q 값                   0.485926     0.477037
  critic별 순위          0.545926     0.505926
네 값은 전부 같은 기존 learner 0/1/2와 BC0에서 측정한 9-task last3 평균이다.
이 탐색 그룹에서는 순위 변환이 도움이 됐지만 중앙값을 추가하는 이득은 없었다.
따라서 평균 순위라는 더 단순한 후보를 우선 확인한다. 평균 순위에는 중앙값의
'둘이 같은 유일 최선 후보를 지지하면 세 번째와 관계없이 선택' 보장은 없다.
이론적 보장 하나만으로 실제 성공률 우위를 판단하지 않고 네 조합을 모두 보고한다.

0.545926은 아직 관찰하지 않았던 새 그룹의 확인 결과가 아니라 탐색 결과다.
새 학습/평가 결과가 존재하기 전에 이 후보를 고정했다. [3,4,5]와 [6,7,8]의
두 새 그룹을 사용하며 BC는 각각 3과 6으로 고정한다. 기존에 등록한 54개
학습 모델을 그대로 재사용하므로 순위 평균 확인을 위한 GPU 학습 추가는 없다.
이전 순위 중앙값 후보도 동일 그룹에서 고정된 비교 대상으로 계속 평가한다.
두 정책의 결과는 서로 독립적인 학습 반복으로 세지 않고, 둘 다 공개한다.

각 task에서 800K/900K/1M CPU50 성공률을 동등하게 평균하고, 9개 task와
새 두 그룹도 동등하게 평균한다. reset seed는 42..91이다. 결측/중단 결과를
0으로 채우거나 task별로 평균/중앙값 중 좋은 쪽을 골라 섞지 않는다.
새 두 그룹 평균과 탐색을 포함한 세 그룹 평균 모두 .47을 넘어야 한다.
최종 검토와 실제 checkpoint/source/optimizer clock/raw episode 검증이 필요하다.
총 학습 비용은 base IFQLV2 3개이며, 1M/member 시 Q 3M, V 6M update다.
FQL과 같은 총 계산량에서 더 좋다는 주장이나 DD-ReBRAC(.63)를 넘는 SOTA
주장은 현재 근거가 없다.

finite min/mean backup, boundary 보강, GMM, 별도 policy-flow 압축 실험은
현재 우선 후보에 모두 합친 기능들이 아니다. 이들은 실패 원인과 대안을
분리해서 보는 연구 가지다. Cube-double에서 mean-backup critic만 바꿔
0→.32가 된 결과와, 일부 환경에서 policy-flow 압축이 실패한 결과는 각각
그 가지의 진단 근거이며 0.545926의 구성 요소로 합산하지 않는다.
