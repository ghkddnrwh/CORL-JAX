OGBench non-default 40 task: 다른 서버에서 gamma=0.999 실행
작성: 2026-11-20

실험 범위

  Finite-mean Lean + 단일 actor, N=9, seed=0, gamma=0.999.
  10개 환경마다 5개 singletask 목표 중 default를 제외한 4개를 독립 학습한다.
  이 서버에서 실행하는 gamma=0.995 실험과 할인율 및 그에 따른 return bound만 다르다.
  기존 default 실험이나 취소한 batch-size/EMA/DR3 실험을 재개하지 않는다.

  환경                              제외할 default   실행할 task
  AntMaze Large / Giant              1               2,3,4,5
  HumanoidMaze Medium / Large        1               2,3,4,5
  AntSoccer Arena                    4               1,2,3,5
  Cube Single / Double               2               1,3,4,5
  Puzzle 3x3 / 4x4                   4               1,2,3,5
  Scene                             2               1,3,4,5

  이름 예: antmaze-large-navigate-singletask-task2-v0.
  각 family는 원본 trajectories 파일을 공유한다. OGBench가 지정한 task의 목표로
  rewards와 bootstrap masks를 다시 구성하므로 task마다 별도로 학습한다.
  공식 정의: https://github.com/seohongpark/ogbench#usage-for-standard-non-goal-conditioned-offline-rl

학습 및 평가 설정

  1M optimizer updates, batch256, Adam LR=3e-4, target EMA=0.005.
  finite expectile=0.9, bootstrap 후보 9개, BC Flow Euler 10 step.
  target critic heads: AntMaze Large/Giant는 min, 나머지는 mean.
  task family의 알려진 reward 범위 / (1-gamma)로 TD target clipping.
  Q 정규화, DR3, EMA 감소, 배치 증가, Q checkpoint 선택을 사용하지 않는다.
  Lean 배포: BC Flow 후보 9개를 online-min-Q로 선택.
  단일 actor: online-min-Q best9 label의 MDN9 likelihood distillation.
  단일 actor 배포: mixture component를 뽑아 그 component location을 실행한다.
  actor는 bootstrap에 쓰이지 않는다. Lean과 actor는 같은 학습 checkpoint를 공유한다.
  800K/900K/1M 각각 Lean/actor CPU50 평가. 독립 episode reset seed=42..91.
  각 task의 주 성능은 세 checkpoint 성공률의 산술 평균이다.
  학습 seed는 하나이므로 시드 간 표준편차를 보고하지 않는다.
  latest.pkl은 10K마다 저장. 평가용 모델은 100K/300K/800K/900K/1M 보관.

1. 코드와 Python 환경

  레포의 루트 디렉터리에서 아래 명령을 실행한다.
  이 파일과 함께 추가된 연구 코드도 다른 서버의 레포에 반영되어 있어야 한다:

    utils/codex/ukjo1/error_propagation/flow_iql_research/
      nondefault_n9_core_v1.py
      train_nondefault_n9_v1.py
      evaluate_nondefault_n9_v1.py
      prepare_nondefault_n9_v1.py
      validate_nondefault_n9_v1.py
      validate_nondefault_controller_v1.py
      run_nondefault_n9_v1.py
      supervise_nondefault_n9_v1.py
      analyze_nondefault_n9_v1.py

  위 모듈들은 같은 폴더의 기존 연구 learner와 vendor/ 코드 및
  ../propagation_research/{reward_bounds,seeded_reset}.py를 사용한다.
  최신 utils/codex/ukjo1/error_propagation/ 전체를 반영하면 된다.
  이 서버의 /home/ukjo1/... 경로나 /data/sda2/... 경로를 사용할 필요는 없다.
  실행 서버에서 prepare를 수행하면 그 서버의 경로와 소스 해시가 새로 기록된다.
  gamma=0.995의 registration/checkpoint를 복사해서 0.999로 재개하지 않는다.

  이미 학습 가능한 동일 환경이 있으면 그것을 활성화한다. 예:

    conda activate ogbench
    python -c "import jax, flax, optax, ogbench; print(jax.devices('gpu'))"

  현재 서버에서 검증한 주요 버전:
    Python 3.10, ogbench 1.2.1, jax 0.4.1, jaxlib 0.4.1+cuda11.cudnn86,
    flax 0.6.1, optax 0.1.3, numpy 1.23.1, scipy 1.13.1,
    gymnasium 1.3.0, mujoco 3.9.0, dm-control 1.0.41,
    ml-collections 0.1.1, distrax 0.1.2.
  CUDA用 jaxlib는 서버의 CUDA/driver와 호환되는 기존 설치를 사용한다.
  prepare가 실제 실행 환경의 버전을 registration_v1.json에 기록한다.
  OGBench 버전 차이는 reward 정의에도 영향을 줄 수 있어 1.2.1을 맞추는 편이 좋다.

2. 실행 경로와 자원 설정

  RUN_ROOT는 이 서버에서 쓰기 가능한 새 경로로 정한다. 아래 예는 레포 내 경로다.
  체크포인트가 많이 저장되므로 필요하면 넉넉한 데이터 디스크의 절대 경로로 바꾼다.

    export RUN_ROOT="$PWD/logs/codex/ukjo1/error_propagation/diagnosis/finite_mean_nondefault40_g0999_n9_seed0_v1"
    export OMP_NUM_THREADS=1
    export OPENBLAS_NUM_THREADS=1
    export MKL_NUM_THREADS=1
    export MUJOCO_GL=egl

  아래 예는 GPU 0/1, GPU당 학습 8개, 총 16개 동시 학습이다.
  현재 서버의 RTX A6000 48GB 두 장 기준 설정이며, 각 학습은 GPU 메모리 10%를 예약한다.
  GPU 메모리가 작으면 --per-gpu 2 또는 4로 줄인다. GPU가 한 장이면 --gpus 0으로 바꾼다.
  --eval-workers 8은 최대값이다. 실제 CPU 수에 맞춰 자동으로 줄어든다.
  평가 작업마다 4코어를 고정 배정하고, 학습 작업에도 별도 CPU를 배정한다.

3. 40개 설정 등록

    python -m utils.codex.ukjo1.error_propagation.flow_iql_research.prepare_nondefault_n9_v1 \
      --root "$RUN_ROOT" --discount 0.999 --gpus 0 1 --per-gpu 8 --eval-workers 8

  데이터 경로 기본값은 ~/.ogbench/data다. 다르면 위 명령에 다음을 추가한다:
    --dataset-dir /path/to/ogbench/data
  없으면 다음 검증 단계에서 필요한 10 family의 train/val 데이터를 다운로드한다.
  모든 task는 검증 단계에서 등록되며 default task는 포함하지 않는다.
  동일 root에서 prepare를 다시 실행하면 동일한 기존 계획을 보존한다.

4. CPU 검증

    CUDA_VISIBLE_DEVICES='' JAX_PLATFORMS=cpu \
      python -u -m utils.codex.ukjo1.error_propagation.flow_iql_research.validate_nondefault_n9_v1 \
      --root "$RUN_ROOT" > "$RUN_ROOT/validation/validation_stdout.log" 2>&1

  validation/numerical_v1.json의 status가 PASS인지 확인한다.
  40개 task ID, 80개 할인율별 config, min/mean 양쪽의 실제 N9 update 수치 일치,
  serialization 후 재개 일치, 원본 데이터 파일 해시를 검사한다.
  최초 실행에는 데이터 다운로드와 JIT compile 시간이 든다.

  이어서 실제 GPU 학습 없이 관리기의 자동 배정/재시도/완료 처리를 검사한다:

    python -m utils.codex.ukjo1.error_propagation.flow_iql_research.validate_nondefault_controller_v1 \
      --root "$RUN_ROOT"

  validation/controller_v1.json도 PASS여야 한다.

5. 지속 실행

    nohup python -u -m utils.codex.ukjo1.error_propagation.flow_iql_research.supervise_nondefault_n9_v1 \
      --root "$RUN_ROOT" > "$RUN_ROOT/supervisor_stdout.log" 2>&1 < /dev/null &

  학습이 하나 끝나면 바로 다음 task가 실행된다.
  checkpoint가 준비되면 별도 CPU 평가가 자동 실행된다.
  관리기 장애 시 supervisor가 관리기를 재시작하고, 살아 있는 작업은 그대로 인계한다.
  학습 프로세스가 비정상 종료되면 저장된 상태와 replay RNG에서 한 번 자동 재시도한다.
  수치적 nonfinite 중단은 자동 재학습하지 않고 별도로 표시한다.

6. 진행 상황과 결과

    python -c "import json,os; d=json.load(open(os.path.join(os.environ['RUN_ROOT'],'controller_status.json'))); print('phase:',d['phase'],'running:',len(d['running']),'pending:',len(d['pending']),'train:',d['training_complete'],'/40','eval:',d['evaluations_complete'],'/240')"

  상세 로그:
    controller_status.json            현재 실행/대기/평가 상태
    controller_stdout.log            관리기 로그
    supervisor_status.json           관리기 감시 상태
    runs/<run_id>/stdout.log         학습 로그
    runs/<run_id>/runtime.json       최근 학습 step
    runs/<run_id>/dataset.json       목표 task, reward/mask 해시, 데이터 출처
    evaluations/<run_id>/*.json      episode별 성공/보상/길이

  중간 결과는 10분마다 자동 집계된다. 바로 집계하려면:

    python -m utils.codex.ukjo1.error_propagation.flow_iql_research.analyze_nondefault_n9_v1 \
      --root "$RUN_ROOT"

  완료 후 자동 생성되는 최종 파일:
    analysis/per_task_final_v1.csv          task40 × Lean/actor의 80행 성능표
    analysis/family_summary_final_v1.csv    family별 non-default 4 task 평균
    analysis/RESULTS_KO_final_v1.txt         읽기 쉬운 40 task 표
    analysis/summary_final_v1.json          완료 수와 검증 결과

  --discount 0.995로 등록하면 같은 코드로 현재 서버와 동일한 할인율 실험이 된다.
  0.995와 0.999는 반드시 별도 RUN_ROOT를 사용한다.

7. 중단 및 재개

  이 연구의 작업만 중단:

    touch "$RUN_ROOT/STOP"

  새 작업 실행이 차단되고, 실행 중인 학습은 현재 scan이 끝나면 체크포인트를 저장하고 종료한다.
  관리기/평가 종료 여부는 controller_status.json에서 확인한다.
  이후 다시 실행하기로 결정했을 때만 STOP을 지우고 5번 supervisor 명령을 실행한다.
  재개 시 기존 RUN_ROOT와 동일 코드를 사용한다. 완료된 작업은 생략한다.
